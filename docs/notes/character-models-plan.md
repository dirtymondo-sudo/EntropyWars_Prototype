# CHARACTER MODELS PLAN — the tracker for all new character-model work

Started 2026-11-01 at mondo's ask: "We need a plan doc to keep track of all this new model stuff and any thread
working on it needs to reference it."

**Rule for every thread that touches character models** (MPFB bodies, the character creator, clothes, hair, sway,
Meshy parts, faces/mouths, wiring a race to a new model): read this file first, work from its table, and update the
row you worked on (status + what's next) in the same PR as your change. Copy the updated file to
`/mnt/project-files/character-models-plan.md` too. Technical detail stays in `models-assets.md` ("THE SWAY",
"THE MPFB BODIES") and `character-creator.md`; this file is the status board, not the notes.

Status words: **DONE** (merged and shipped), **IN PROGRESS** (a thread is on it now), **NOT STARTED**,
**WAITING ON MONDO** (needs his call or his Meshy work).

## 2. Decisions mondo has made (do not re-ask)

- Base bodies + faces = **MPFB2 (MakeHuman)**. NOT Quaternius bodies.
- **Claude runs Blender headless in the cloud** (`pip install bpy==5.2.3`). No device connection, no Blender on his side.
- Claude **tells mondo what to make on Meshy**: solid pieces (hats, horns, helmets, crowns, heads, tails, wings).
  Meshy is NOT used for soft clothes (it makes closed lumps that don't fit a body).
- Clothes = **real meshes fitted to the MPFB body** (MakeHuman pack clothes, plus pieces Claude builds in cloud Blender),
  replacing the code-generated shells over time. The classic MALE / FEMALE bodies and the existing coded garments STAY
  as picks until mondo says otherwise (never delete content he didn't name).
- **Sway = spring bones**, not cloth simulation. Cosmetic, runs on each screen, nothing relayed online.
- Mouths: not top priority. MPFB heads already carry 52 ARKit face shapes + 15 visemes, so humans need no separate head.
  Creature heads will be separate pieces with a jaw bone.
- CC-BY packs are allowed; keep the credits list. Face shapes stay in (he tests on his own PC; don't cut them for the
  friend's PC).
- MPFB bodies are NOT wired to any race yet; that needs mondo's OK per race.
- **Fit clothes to the MPFB bodies ONLY** (mondo 2026-11-03, `cmsg_01XWpxyTn3nnw98znVzKdFjsTUS1PNwrfzz73n7w7n3Qfo`: "the clothes
  just fit better with the mpfb bodies (not the classic), so we'll use those from now on and you dont have to worry about fitting
  stuff to the mpfb classic bodies anymore"). Check and fix clothes on `mpfb_male` / `mpfb_female` (and the other MPFB builds);
  don't spend work fitting to `mpfb_classic_*` or the classic Meshy bases. Keep those bodies as picks (never delete content he
  didn't name); they just don't get fitting passes.

  body's shape. Putting one on the robot means Claude refits it to the robot in cloud Blender: shrink-wrap the garment
  onto that model's surface and copy its bone weights across. That is automatic per model, so mondo makes nothing
  extra, but it only works on roughly human-shaped models (robot, cyborg, ai, yeti, golem...), it is one file per
  garment per model, so it is done per race on request rather than for every garment on every model, and very bulky
  shapes (King Kong, juggernaut) will look stretched. A tie, badge or medal is a solid piece and just pins to the chest.
- Online: both screens already play the cast and its effects, so a held prop is part of that same moment. When it is
  built it rides the existing cast relay (RULE #2), with no new state.

## 7. The AAA creator: what MakeHuman offers and how it reaches the game (2026-11-02, rows 25-29)

mondo asked (11-02): were there other face / head options, is there an established way to use these models in a creator,
what about female short / thick / tall-thin, can we control eye and lip size like a AAA creator, doesn't the head have
more bones. Answers, measured on the MPFB2 checkout (HEAD 6ff1eb35) and the pack catalogue:

- **MakeHuman IS a slider creator.** Every slider is a "target" (a morph: per-vertex offsets on the shared hm08 mesh).
  MPFB2 ships ~1,250 of them; until 11-02 the game used 9 (build, chest, bust, waist, hips, head width, jaw width, nose,
  cheeks). Face alone: eyes 68, mouth 44, nose 42, ears 44, head 27 (incl. 7 head shapes), neck 20, cheeks 16, chin 15,
  forehead 8, brows 6. Body: arms 50, legs 58, torso 34, feet 30, hands 22, hips 14, stomach 8, breast 228 (cup/firmness
  grid). The packs add 160 community targets (131 CC0, 29 CC-BY), incl. animal heads and muzzles (row 28).
- **The plumbing already existed** (PR #739): `bake-mpfb.py --shapes` writes the targets sparse into
  `mpfb/mpfb_shapes.glb`; three-renderer.js `shapeBody` adds them to the bind-pose skin once when a look builds, by
  `_BASE_INDEX`, on every MPFB body and the MPFB classic bodies' MPFB head. Clothes, hair and hats already follow the skin.
  Phase 1 only adds keys: `SHAPE_TARGETS` (bake), `EW_MPFB_FACE_SLIDERS` (sprites.js: groups + labels, limits -1..1),
  `FACE_KEYS` (three-renderer.js), the FACE tabs (party-builder.js). No new mechanism. Not online-relevant: the look is
  the appearance object every client already builds itself.
- **Range:** MakeHuman's own +-1 is the shipped range. Pushed to 2x (proof image) the eye lids gap, the nose bridge
  creases and the forehead flattens, so wider ranges need per-slider testing.
- **Female short / thick / tall-thin:** the five MPFB bodies are five macro presets (bake-mpfb.py BODIES); heavy, thin
  and short are all male (gender 1.0 / 0.8). MakeHuman's macros (gender, age, muscle, weight, height, proportions) blend
  "universal" targets. Weight / muscle deltas on the female are skin-only, ~90 KB each (row 26). Height / proportions /
  limb lengths also move the bones: MPFB places every bone at a "joint-*" helper cube, which the targets also move, so a
  per-slider joint offset can be baked and the bind skeleton moved at build (row 27). Fallback = bake more presets: ~2.7 MB
  a body + one more fitted morph in every one of the 476 pack garments.
- **Bones:** our bodies use MPFB's `game_engine` rig (52 bones, no face bones). MPFB's `default` rig has ~60 face bones
  (jaw, eyes, tongue, lips = oris / levator / risorius, lids = orbicularis / oculi, temporalis) made for posing
  MakeHuman's expressions, not for face shape. AAA face SHAPE is mostly blendshapes; morphs baked once into the mesh cost
  nothing per frame, while 60 more bones per unit would cost skinning every frame on every unit and every library clip
  would need retargeting onto them. Expressions are already covered by the 52 ARKit + 15 viseme morphs (row 21 / 21b).
  Recommendation: no face bones.
- **Weights (phase 1):** mpfb_shapes.glb 637 KB -> 1.75 MB raw (~310 KB gzip, brotli on the CDN), loaded once a session,
  shared by every MPFB body. CPU: only moved sliders are added, once per look build (a few hundred to a few thousand
  vertices each); zero per-frame cost on the board. Memory: the per-vertex tables are now cached per body mesh (were one
  copy per unit). Could be halved later with int16 offsets.
- **Licences:** MakeHuman's own targets (all of phase 1-3) are CC0. Only the CC-BY community targets (row 28) need credits.
- **Community references for good-looking faces (asked 11-03):** none that plug in. MakeHuman's community shares characters as
  .mhm files (slider values for MakeHuman's own modifiers, CC0 output), but there is no curated "attractive face" preset library,
  none of the 64 asset packs carries a .mhm, and MakeHuman's forum / docs only describe what each slider does. Because our FACE
  sliders ARE MakeHuman's own modifiers (with SHAPE_GAIN on top), any .mhm's face lines would map across key by key (divide by the
  gain), so a CC0 .mhm he likes can be dropped in later. The defaults (row 29a) follow the usual attractiveness cues instead
  (averageness, clear dimorphism: jaw / chin / brow for the male; smaller jaw, high cheekbones, almond eyes, small nose for the
  female). The CC0 nose01 / cheek01 pack targets (row 28) would add finer shapes; not needed for the defaults.
