11-01 mondo: Balance Lab "loads really slow/freezes in between matches, on the party builder screen ... is it the map? cycle the same 5 random maps?". Thread "Fix AI training freezes between matches" (it was the Balance Lab). PR #720 merged, zip ENTROPY_WARS_SYNC_20261101-0358 (battle/data/map/three-renderer.js), token 20261101-labgap-01-cors.

Cause (CPU profile cut to the time between matches): not the builder. data.js hqTerrainCompile (14-17 s per big room in the sandbox) ran (1) on the builder screen for a room the lab hadn't played yet, and (2) at EVERY battle start, because _hqBuildRoomInBattle builds from an Object.assign copy (that drops non-enumerable _terrainInfo) and hqTerrainDoorY recompiled on the copy with a null seed. That second compile also hit VS CPU arena fights and HQ encounters. Shader links: the lab pool = 71 boards / 36 rooms at ~25 programs each, which overflowed the 640 kept-program cap.

Fix: hqTerrainDoorY reads the room row's record for a copy (same terrain+shell); map.js _simWarmNextMap surveys the next lab map in the worker; three-renderer.js _ewKeepScale keeps 3x the programs while state.devAutoSim; new Map dropdown option rotate5 (_trainMapFew, default stays full rotation).
