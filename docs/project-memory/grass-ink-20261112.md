mondo 11-12 (Training Room screenshots, Firefox Mac): "adding the ink shader makes the grass look kinda weird to me, like it ends up being a shadowy blob. Can we exclude grass from the shader or tweak whatever is causing that?" Thread (thread in the owner project). Related [[shader-style-20261112]] [[grass-field-20261112]].

- CAUSES: (1) the style's five light bands split each clump into bright tip + near-black foot; (2) ink lines of the square seams drew across the field (tufts write no depth, so the pass saw the ground under them).
- FIX PR #1215 (?v=20261112-grassink-01-cors; three-post.js 4cac7552, three-renderer.js 93cc4edc live): the style mask draws the grass mesh once more, alone, writing tuft view depth (log2(1+z)/20 in green+blue); the style pass applies grade only (no bands, no line) where the scene is at or behind the tuft. Trees, walls, bodies in front keep bands + line. Grade look, unit ink, all settings unchanged. Old look live: `window.EW_INK_ON_GRASS = true`. Notes: docs/notes/rendering-loading-perf.md "THE GRASS TAKES NO INK".
- ALSO FIXED (same PR): the style's unit mask was drawn once and then held (bug from the Unit Lines PR #1200), so the bold unit line sat on first-frame silhouettes. Now redrawn every frame.
- LESSONS: do not encode mask depth with camera near/far (mask and scene disagreed by ~1.8x); `renderer.render(mesh, cam)` draws one mesh alone on both renderers; headless default here is the pmndrs chain, `?ew_gpu=webgl2` forces the node renderer. A kept-open Playwright page that evals a cmd file beats 3-minute reload shots.
- Seen: Training Room (pmndrs chain + node WebGL 2), Fairy Forest (node WebGL 2). Proof /mnt/project-files/grass-ink-20261112/. NOT seen: real WebGPU / his Mac, legacy composer, split-screen panes, rigged units standing in grass. Cost: one extra half-size draw of the grass while Grade + Ink is on (not measured on a real GPU).
- Side effect to watch: tile highlight frames lying on grass lose their thin ink outline (2.5 px mask dilation).
